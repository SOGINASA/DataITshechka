## Реализованные требования бэкенда

| Требование | Реализация |
|---|---|
| Начальная конфигурация из PDF | `checklists/freedom_chat_v1.json`, команда `seed-checklist` |
| Редактирование критериев, типа, веса, N/A и шкалы | `POST /api/checklists`; сохранение изменённой конфигурации через `POST /api/checklists/{id}/versions` |
| Новый критерий без изменения кода | В Ollama передаются актуальные формулировки и параметры всей выбранной версии |
| RU, KZ, EN; оператор, бот и система | Импорт `ru/kk/en`; в модели оценивается оператор, остальные роли служат контекстом |
| Оценка каждого критерия, доказательства | `value`, `status`, `points`, `weight`, `explanation`, `evidence`, `reviewed_range` |
| Числовые шкалы | Допускаются только заданные ступени; вес умножается на отношение значения к максимуму шкалы |
| N/A | Только разрешённые критерии, условие в конфигурации, обязательное объяснение; вес исключается из знаменателя |
| Итог и секции | `score`, `final_score`, `score_is_partial`, `coverage`, `sections`; округление HALF_UP до 2 знаков |
| Грубая ошибка отдельно | `answer_type=flag`, вес 0; `gross_error_detected`, без обнуления балла |
| Апелляция и решение — разные действия | Создание `Appeal`, затем `/api/appeals/{id}/decision` с `confirm` или `change` |
| Исходная оценка и финальное решение | `original_results`, `original_summary`, текущие `results`, история `reviews`, снимок `disputed_result` в апелляции |
| Защита от потери ручных изменений | `expected_revision`, условное обновление оценки и атомарное закрытие апелляции; повтор/конфликт даёт 409 |
| Контрольный набор | Явный `group_id` через `/api/datasets/import` или CLI `import-dataset --group ...`; фильтр списка `dataset_group_id` |
| Исходные метки времени | `source_metadata.source_timestamps`, тип отсчёта и сохранённая исходная дата |
| Без регистрации | API прототипа остаётся без входа; подписи автора и проверяющего не аутентифицированы |

## Официальные критерии

| ID | Тип | Вес | Допустимые ответы | N/A |
|---|---|---:|---|---|
| `contact` | binary | 10 | Да / Нет | Нет |
| `needs` | binary | 15 | Да / Нет | Данных для ответа хватало с самого начала |
| `identification` | binary | 20 | Да / Нет | Запрос не требовал идентификации |
| `consultation` | scale | 20 | 0, 5, 10, 15, 20 | Чат закончился до формулировки запроса |
| `empathy` | binary | 15 | Да / Нет | Нет |
| `dialogue_management` | scale | 15 | 0, 4, 7, 10 | Нет |
| `closing` | binary | 5 | Да / Нет | Чат оборвался до возможности завершения |
| `gross_errors` | flag | 0 | Да = нарушение; Нет = не выявлено | Нет |

Сумма весов — 100. Например, при N/A для `needs` и `identification`, консультации 15/20, ведении диалога 7/10 и остальных положительных балльных критериях: `(10 + 15 + 15 + 10.5 + 5) / 65 × 100 = 85.38`. Грубое нарушение не меняет это число, но отображается отдельно.

`score` может быть предварительным, если часть критериев ещё не оценена; это явно обозначено `score_is_partial=true` и покрытием. `final_score=null`, пока остаются неоценённые критерии с весом. Неизвестное состояние флага — `gross_error_detected=null`; оно не считается отсутствием нарушения. `needs_review` остаётся true для непроверенных человеком выводов модели. Арифметика корректна независимо от качества модели; смысловая обоснованность решения требует проверки.

## Ollama

Подготовлен клиент нативного `POST /api/chat` с `stream=false` и JSON Schema в `format` согласно [официальному API Ollama](https://github.com/ollama/ollama/blob/main/docs/api.md). Модель и сервер не устанавливались. Имя модели выбирается через `OLLAMA_MODEL`; локально Ollama в доступном окружении не обнаружена.

В запрос отправляются текст диалога, язык, канал и актуальный чек-лист. Подписанные ссылки API/аудио и другие поля конфигурации в модель не отправляются. Реплики всех ролей объявлены данными, а не инструкциями. Модель не получает инструменты или доступ к URL.

Сервер отклоняет неполный или обрезанный ответ, пропуск/повтор критерия, несуществующие ID реплик, запрещённый N/A и значения вне шкалы. Цитаты подставляются сервером из транскрипта, а баллы рассчитываются локально. Ошибка модели даёт 502/503 без сохранения фиктивной успешной оценки. Автоматических повторов нет.

В `run_metadata` записываются модель, версия промпта, число вызовов, время и доступные счётчики токенов. Качество, скорость и фактические расходы на VPS пока не измерены. Используется один запрос на оценку; тариф платного API не применяется к этому локальному адаптеру, стоимость оборудования и вычислений не оценивалась.

## Что остаётся за пределами этой проверки

- Подключение фронтенда: формы изменения чек-листа, подачи апелляции, отдельное действие проверяющего, переход к репликам и плеер. API для этих действий готов; UI не изменялся в этой работе.
- Установка и выбор модели Ollama на VPS, реальный прогон и проверка смыслового качества на RU/KZ/EN. Синтетические ответы модели в тестах подтверждают контракт, а не точность.
- Реальный контрольный `group_id` ещё не предоставлен; путь проверен на синтетической группе, чужие группы не запрашивались.
- Аудиоплеер и точность синхронизации. Время звонка отсчитано от первой реплики, исходные даты сохранены; совпадение с началом аудиофайла не подтверждено.
- Docker/PostgreSQL runtime и развёртывание. Локальная миграция SQLite выполнена с резервной копией, 65 диалогов сохранены.
