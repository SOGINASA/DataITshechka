# Полное сравнение локальной версии и ML2

Дата: 7 ноября 2026. Пользователь выбрал сравнение готовых кандидатов:
локальная реализация с `qwen3:4b` против ML2 с исходной `qwen3:8b`.
Проверяется весь DEV: 60 чатов и 5 звонков, 520 решений.

## Что найдено в приложенной папке

`runs/collected-tests-2026-11-07/` содержит семь сохранённых запусков на шести ID:
шесть ответов `ok`, один `error`. Для `p1-ru-004` сохранены и незавершённая
генерация, и последующий успешный запрос. `ok` означает, что ответ обработан;
точность относительно человеческих меток из этого статуса не следует.

Только `p1-ru-021` полностью совпадает с замороженным DEV по тексту и ролям.
На нём архивный ответ совпал с 6 из 8 эталонных решений; итог 100 против 92,31.
У `p1-ru-004` отличается реплика 12, у `p1-kz-010` — 6 и 11: встречаются
опечатки и смешение алфавитов. Остальные примеры отсутствуют в нашем DEV.
Поэтому архив нельзя использовать как полноценный конкурентный прогон на тех же
исходных данных. Исходные архивные файлы не исправляются и не перезаписываются.

Подробности: `data/runs/full-compare-20261107/archive-audit.json`.

## Общие данные и ограничения сравнения

Используется неизменённый `data/releases/dev-reviewed-v1`: тексты, порядок реплик,
стабильные ID и подтверждённые метки. Голосовая рубрика берётся из этого же v1.
Новая политика voice-v2 и предложенный, пока неподтверждённый N/A для одного
приветствия не подставляются в эталоны во время эксперимента.

У конфигурации A обнаружены 422 на `p1-ru-010` и `p4-ru-004`: расширенный промпт
вместе с этими диалогами не проходит её лимиты. Эти ошибки сохраняются в основном
прогоне и знаменателе метрик; параметры уже начатого эксперимента не меняются.

Оба кандидата получают одинаковые определения критериев из снимка, включая шкалы
и условия N/A. У ML2 меняется файл конфигурации относительно архивных ручных
запусков: это нужно, чтобы отличия правил не выдавались за выигрыш алгоритма.
Используются собственные промпты, схемы ответа и валидаторы каждого кандидата.
Готовые ответы, человеческие обоснования и исключённые разметчиком диапазоны
не отправляются ни одной модели. Аудио и база знаний не подключаются.

Это development с исходными AI-ответами и последующим подтверждением пользователя,
без независимого holdout и без группировки близких сценариев. Метрики помогают
выбрать следующий кандидат для проекта, но не доказывают качество на контрольном PROD.

Digest 8B проверяется на точное совпадение с приложенными ответами.
Контекст ML2 увеличен относительно исходных 20480: одинаковые полные рубрики
и транскрипты не проходят его консервативную проверку в исходном лимите.
Ни один текст не сокращается. Разные модели, thinking и таймауты означают сравнение
полных кандидатов, а не изолированное сравнение качества Python-кода.

Два прогона используют GPU последовательно, чтобы модели не вытесняли друг друга.
Фактическая скорость измеряется на Windows / RTX 4050 Laptop 6 ГБ; времена архивных
запусков с Apple M4 не считаются результатами на этой машине.

## Исправления совместимости ML2

Файловый ввод/вывод явно использует UTF-8 вместо кодировки Windows по умолчанию.
Хеши путей используют POSIX-разделитель. Исправлено закрытие HTTPError без тела
для установленного Python 3.11.0. Содержание промпта, алгоритм принятия решения,
число попыток и расчёт баллов ML2 не менялись. Исходники копируются в артефакты запуска.

Проверки после исправления: 32 теста ML2 прошли; общий запуск backend-проверок
с тестами сравнения — 124 теста прошли. Тестовый транспорт не измеряет точность LLM.

## Как читать итог

Основной знаменатель — все 520 решений; ошибки, отсутствующие строки и needs_review
не удаляются из него. N/A — отдельное окончательное решение, а не ошибка.
Отдельно считаются языки, каналы, критерии, точные ступени шкал, N/A и C8.
MAE показывается вместе с числом полных оценок. Для прямого сравнения MAE также
используется общий набор диалогов, где оба кандидата выдали полный итог.
Отдельный срез показывает звонки, проверенные человеком с аудио.

Для решения о внедрении нужно смотреть не только общую точность, но и пропуски
грубых нарушений, полноту оценок, технические ошибки и время работы.
Существование цитаты проверяется программно; её смысловую уместность проверяет человек.

## Команды и артефакты

Из корня репозитория:

```powershell
.\backend\.venv\Scripts\python.exe scripts/compare_ml_versions.py prepare
cd backend
.\.venv\Scripts\python.exe -m ml.run --run-dir ../data/runs/full-compare-20261107/local-v1
cd ..
.\backend\.venv\Scripts\python.exe scripts/compare_ml_versions.py run-ml2 --wait-local
.\backend\.venv\Scripts\python.exe scripts/compare_ml_versions.py report
```

Каталоги уже созданного эксперимента не перезаписываются. Прерванный запуск
продолжается соответствующей командой с `--resume`, при совпадении всех настроек
и исходников. Сохранённые ошибки не превращаются в успешные ответы при resume.

`data/runs/full-compare-20261107/` содержит общий контракт, входы, эталоны,
аудит архива, `local-v1/`, `ml2-8b/` и `comparison-metrics.json`.
Всё это исключено из публичного Git. Итоговый сравнительный отчёт формируется
после завершения всех 65 записей у обоих кандидатов; промежуточные метрики
не объявляются финальными.
