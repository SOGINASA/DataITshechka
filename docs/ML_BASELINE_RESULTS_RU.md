## Что обнаружено

Модель завышает оценки: не выбирает N/A даже при выполненном условии, иногда
принимает совет за уточнение запроса, а ранний ответ — за итог при завершении.
На полноте консультации пропускает частичные ступени. Синтаксически корректный JSON
эти ошибки не устраняет. В таком состоянии автоматические оценки нужно проверять человеку.

До финального прогона сохранены диагностические запуски `control-v1`, `control-v2`,
`diagnostic-v1`, `control-v3`: обнаружены пустые доказательства/диапазоны и статус pass
при числовой шкале. Последующие запуски ограничивают схему отдельно для каждого
критерия, требуют диапазон и выбирают ID из реальных реплик. Сервер по-прежнему
проверяет ответ, а не исправляет плохие решения эталонной разметкой.
Прерванные запуски не выдаются за полную оценку качества.

Первый диалог с f16-кэшем и контекстом 32K занял 175,42 сек; финальный профиль
q8_0/24K генерировал около 32–33 токенов/сек вместо примерно 8–9.
Между запусками также менялись промпт и схема, поэтому это не изолированный
эксперимент о влиянии одного параметра на полное время ответа.

## Артефакты и продолжение

Локальные артефакты: `data/runs/qwen3-4b-control-v4/` — `run.json`, `inputs.json`,
`references.json`, `predictions.json`, `responses/`, `metrics.json`.
Они содержат приватные входы и не включены в публичный Git.
Проверен отдельный запрос через Flask API: HTTP 201, `engine=ollama:qwen3:4b`,
восемь результатов сохранены в БД с происхождением model, без человеческого подтверждения.

Отдельно через API обработан полный транскрипт `p4-ru-002` с новой голосовой рубрикой
`voice-adapted-2`: HTTP 201, восемь решений, 88,80 сек, контекст 40960,
выход до 3072, 7644 входных и 1346 выходных токенов. Аудио модели не передавалось.
Это проверка работоспособности длинного контекста на одном звонке, а не измерение
качества пяти звонков. По контакту модель выбрала pass; предложение N/A из новой
разметки остаётся на ручную проверку. Итог модели 100 нельзя считать подтверждённым
баллом качества. Артефакт: `data/runs/api-voice-v2-smoke.json`.

Следующий эксперимент должен решать одну проблему: применение N/A. Например,
проверить обоснование перед вердиктом или включённый reasoning на той же небольшой
выборке, затем проверить другие сценарии. Не объявлять улучшение на этих десяти
обобщающим качеством. До few-shot/обучения назначить scenario_group, разделяя
переводы и варианты одного сценария вместе.

Затем прогнать все 65 с отдельным профилем длинного контекста для звонков.
Для звонков зафиксировать, что модель видит только транскрипт. Новая голосовая
политика v2 допускает N/A при незаписанном приветствии; её нельзя напрямую сравнивать
с прежними эталонами v1. Для v2 один предложенный ответ пока ожидает проверки.

Расширять синтетику и начинать дообучение сейчас преждевременно: сначала нужно
исправить наблюдаемые ошибки применения рубрики и получить сравнимые измерения.
