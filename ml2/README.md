# ML2 — независимая версия оценщика CQA

Локальный Python-модуль для второй реализации. Он не импортирует backend/frontend,
не меняет их API, не пишет в общую БД и не отправляет диалоги в облако.
Python 3.11+, только стандартная библиотека; модель вызывается через уже установленный Ollama.
Обучения с нуля и автоматического скачивания весов нет.

## Что реализовано

- Чек-лист из JSON: новые критерии, веса, шкалы, N/A без изменений Python-кода.
- Отдельные версии чатов и звонков; C1 N/A для подтверждённого обрезанного начала звонка.
- Один запрос на диалог; один повтор при неверной структуре/ссылках, без повторов сетевых ошибок.
- Проверка каждого ответа, полярности флагов, шкал, критериально-специфичных доказательств,
  областей просмотра и источников знаний. Цитата обязана находиться внутри просмотренного диапазона;
  успешные решения требуют прямой реплики оператора. Завершение, контакт и полный разбор разговора
  имеют отдельные проверяемые диапазоны.
- Модель выбирает ответ; `pass/fail/scored` выводятся из него программно. Формат обмена
  результатов остаётся единым, без противоречивой пары ответа и статуса.
- Decimal/HALF_UP, перераспределение N/A, неполная оценка, отдельный флаг грубой ошибки.
- Простой поиск по официальным выдержкам с версиями и сроками действия; без выдуманной базы.
- Пакетный прогон с сохранением после каждого диалога, продолжение прерванного запуска,
  JSONL и CSV, версии и хеши всех входов.
- Одинаковый инструмент измерения и попарного сравнения двух кандидатов; ошибки остаются в знаменателе.
- Экспорт и отдельная проверка официального JSON 1.0; общий лимит контрольного запуска.

Это ML-библиотека, CLI и отдельная локальная страница для проверки. Подключение к основному
приложению — отдельный согласованный шаг с бэкендером. Не реализованы собственный STT, просодия, очередь основного приложения и апелляции:
они относятся к другим этапам/существующему приложению. Обоснованность текста проверяется человеком;
валидный ID цитаты сам по себе не подтверждает логический вывод.

Порядок сдачи DEV/PROD, команды экспорта, ограничение одного часа и уточнения по
звонкам/идентификации: [SUBMISSION.md](SUBMISSION.md).

## Быстрый запуск

### Страница для ручной проверки

В первом терминале запустите локальную модель (если сервер на этом порту уже работает,
повторный запуск не нужен):

```sh
OLLAMA_HOST=127.0.0.1:11435 OLLAMA_NO_CLOUD=1 OLLAMA_NUM_PARALLEL=1 OLLAMA_MAX_LOADED_MODELS=1 OLLAMA_FLASH_ATTENTION=1 OLLAMA_KV_CACHE_TYPE=q8_0 ollama serve
```

Во втором терминале из корня репозитория:

```sh
ML2_OLLAMA_URL=http://127.0.0.1:11435 python3 -m ml2.web --port 8765
```

Открыть **http://localhost:8765**. Можно вставить текст с ролями `Клиент:` / `Оператор:`
(также поддерживаются бот/система и английские названия), JSON одного диалога или массив
реплик. Можно загрузить `.txt`/`.json` диалога, отдельно подключить JSON базы знаний до 1 МБ
и скачать результат оценки.

Одновременно выполняется один запрос к модели, общий лимит — 10 минут. Обновление
страницы не прерывает оценку. Ввод, результаты и история сохраняются в `ml2/runs/web/`
вне Git. После остановки сервера незавершённый запуск помечается ошибкой при следующем
старте, а не возобновляется сам. Страница привязана к `127.0.0.1`; это локальный
инструмент, не публичное API основного приложения. Можно подключить JSON базы знаний до 1 МБ
с официальными выдержками и при необходимости указать дату диалога. Источники со сроком действия
не используются без даты. Поддерживаемая форма показана в `ml2/examples/knowledge.json`.
Без подходящего официального источника существенные внешние факты должны получить `needs_review`,
а не уверенную оценку.

Интерфейс написан на TypeScript и обычном DOM; готовый `app.js` хранится рядом,
поэтому для запуска Python-сервера сборка не требуется. После редактирования `app.ts`:

```sh
frontend/node_modules/.bin/tsc ml2/web_ui/app.ts --target es2022 --module es2022 --lib es2022,dom --strict --outDir ml2/web_ui
```

### Консоль

Команды из корня BimBomBam. Запустить локальный Ollama (`ollama serve`) и проверить:

```sh
python3 -m ml2 doctor
python3 -m unittest discover -s ml2/tests -v
python3 -m ml2 run --input ml2/examples/dialogue.json --output ml2/runs/my-smoke --purpose synthetic_smoke
python3 -m ml2 export --predictions ml2/runs/my-smoke/predictions.jsonl --output ml2/runs/my-smoke/results.csv
```

Переменные описаны в `.env.example`; CLI читает их из окружения, файл сам не загружает.
Для отдельного порта задайте `ML2_OLLAMA_URL=http://127.0.0.1:11435`. `doctor` показывает
наличие модели и её digest. Он ничего не скачивает и не запускает оценку.

На проверенном Mac с 16 ГБ использовался отдельный локальный процесс Ollama:

```sh
OLLAMA_HOST=127.0.0.1:11435 OLLAMA_NO_CLOUD=1 OLLAMA_NUM_PARALLEL=1 OLLAMA_MAX_LOADED_MODELS=1 OLLAMA_FLASH_ATTENTION=1 OLLAMA_KV_CACHE_TYPE=q8_0 ollama serve
```

В другом терминале перед командами CLI:

```sh
export ML2_OLLAMA_URL=http://127.0.0.1:11435
export ML2_RUNTIME_NOTES='Flash Attention=1; KV cache=q8_0; concurrency=1'
```

По умолчанию `ML2_THINK=true`, контекст 20480, лимит ответа 2048 токенов,
таймаут одного запроса 600 секунд. Режим рассуждения выбран после локальной проверки
ошибок быстрого режима, но его точность ещё требует независимой оценки.
`ML2_THINK=false` доступен для сравнения; первый такой прогон дал содержательные ошибки.
Для Qwen3 используются `temperature=0.6`, `top_p=0.95`, `top_k=20`, `min_p=0`
и seed=7. Все параметры записываются в манифест. Ранее temperature=0 переопределяла
рекомендованные настройки модели; в thinking-режиме авторы Qwen предупреждают
о риске повторений при greedy decoding. См. [карточку Qwen3-8B](https://huggingface.co/Qwen/Qwen3-8B#best-practices).
Лимит 4096 токенов — ограничение нашего запуска, не требование организаторов.
При его достижении результат остаётся ошибкой; код причины и счётчики сохраняются,
обрезанный ответ не превращается в готовую оценку.
Это стартовые параметры, не обещание скорости. Квантование KV-кеша снижает расход памяти,
но его влияние на качество тоже нужно измерять; описание параметров — в
[Ollama FAQ](https://docs.ollama.com/faq). Не запускайте второй сервер на уже занятом порту.

На каждый эксперимент — новый каталог. Сохранённые результаты не перезаписываются.
Для прерванного запуска та же команда с `--resume`: входы, код, модель, правила и параметры
должны совпадать. Сохранённая ошибка остаётся ошибкой; её повторная проверка — новый эксперимент.
Если процесс оборвался посреди строки JSONL, восстановление останавливается, не скрывая повреждение.

## DEV и входные данные

В `case` есть руководство, чек-лист и подписанная ссылка API, но нет базы знаний или
подтверждённой разметки. DEV был получен по этой ссылке и сохранён в `ml2/data/dev.raw.json`.
`data/` и `runs/` исключены из Git: там могут быть тексты диалогов и приватные ссылки.
На другой машине нужно положить свой разрешённый экспорт организатора или backend.

```sh
python3 -m ml2 normalize --input ml2/data/dev.raw.json --channel chat --output ml2/data/dev.chats.jsonl
python3 -m ml2 normalize --input ml2/data/dev.raw.json --channel call --output ml2/data/dev.calls.jsonl
python3 -m ml2 run --input ml2/data/dev.chats.jsonl --limit 3 --output ml2/runs/dev-first
python3 -m ml2 run --input ml2/data/dev.calls.jsonl --rubric ml2/configs/voice.json --output ml2/runs/calls-first
```

Нормализатор принимает ответ организатора `{isSuccess,data:{total_records,records}}`,
`{conversations:[...]}`, массив объектов, отдельный объект или JSONL.
Нормальная форма диалога:

```json
{"conversation_id":"example","language":"ru","channel":"chat","start_truncated":false,
 "messages":[{"id":"m1","speaker":"client","text":"Здравствуйте"}]}
```

Роли: client/operator/bot/system; языки ru/kk/en. Текст и ID сохраняются.
Временные метки не превращаются в неподтверждённые аудиотаймкоды. `start_truncated`
задаётся только при известном обрезанном начале; отсутствие приветствия этого не доказывает.
Для проверки голоса нужна явно выбранная версия правил. CLI не меняет чатовый чек-лист молча.

## Подключение базы знаний

`ml2/examples/knowledge.json` показывает формат на явно синтетическом источнике.
Он не является регламентом Freedom и не используется по умолчанию.
Разбейте полученные официальные документы на самостоятельные выдержки до 4000 символов;
сохраните источник, версию, ID, заголовок и даты действия. Укажите `--knowledge файл.json`.
Для выдержек с датами нужен `--as-of YYYY-MM-DD`, соответствующий дате оцениваемого диалога.
Не подставляйте сегодняшнюю дату автоматически для исторических разговоров.

```sh
python3 -m ml2 run --input ml2/data/dev.chats.jsonl --knowledge ml2/data/knowledge.json --as-of 2026-11-07 --output ml2/runs/with-knowledge
```

Поиск лексический, без перевода/эмбеддингов. Проверяйте покрытие RU/KZ/EN и используйте
проверенные теги/выдержки на соответствующем языке. Нет подходящей выдержки — модель
должна вернуть needs_review для существенного непроверяемого факта. Есть ID источника —
это проверяемая ссылка, но фактическое соответствие источника выводу ещё требует контроля.

## Сравнение с версией другого участника

Согласовать одинаковые входы, рубрику и проверенную разметку. Формат одной строки gold:

```json
{"conversation_id":"example","conversation_hash":"SHA256 нормализованного диалога",
 "rubric_hash":"SHA256 нормализованного чек-листа","language":"ru","channel":"chat",
 "label_source":"human_reviewed",
 "results":[{"criterion_id":"contact","status":"pass","value":true}]}
```

Хеши берутся из `provenance` результата/`manifest.json` запуска или через `ml2.contracts.digest`.
Разметка содержит только реально проверенные решения. Непроверенные поля исключаются
и одинаково отсутствуют для обеих версий; нельзя объявлять ответы самой модели эталоном.
`label_source`: human_reviewed / organizer_ground_truth / synthetic_test.
Для итогового MAE нужны все критерии. Автоматически сгенерированного Ground Truth здесь нет.

Формат предсказания другой версии: `conversation_id`, `status:ok|error`, `results` с
`criterion_id/status/value` и `provenance:{conversation_hash,rubric_hash,elapsed_seconds}`.
Остальные поля нашего результата можно сохранить. Статусы и шкалы должны совпадать с рубрикой;
невалидный ответ не засчитывается. Разные диалоги, дубликаты или рубрики вызывают ошибку.

```sh
python3 -m ml2 score --gold ml2/data/labels.jsonl --predictions ml2/runs/a/predictions.jsonl --output ml2/runs/a/metrics.json
python3 -m ml2 compare --gold ml2/data/labels.jsonl --predictions ml2/runs/a/predictions.jsonl --other ml2/runs/b/predictions.jsonl --output ml2/runs/comparison.json
```

Отчёт: точность по решениям, макросреднее критериев, RU/KZ/EN, N/A/ступени в матрицах ошибок,
C8 precision/recall, полные оценки, MAE и его знаменатель, ошибки и попарные изменения.
При пустом классе неопределённая метрика равна null. Отсутствующие предсказания, невалидные
ответы и needs_review не исключаются из точности. Победитель автоматически не назначается.
Порядок честного сравнения и бюджет первого этапа — в `EXPERIMENT.md`.

## Использование как библиотеки

```python
from ml2.engine import Evaluator
from ml2.provider import Ollama, Settings
from ml2.contracts import read_json
from ml2.knowledge import KnowledgeBase

engine = Evaluator(Ollama(Settings.environment()), read_json('ml2/configs/chat.json'),
                   KnowledgeBase.load(None))
result = engine.evaluate(read_json('ml2/examples/dialogue.json'))
```

`result.results` содержит ответы и извлечённые цитаты, `summary` — серверный расчёт,
`provenance` — версии/хеши/время. Для интеграции API-адаптер должен сохранить результат
как отдельную исходную оценку; не отправлять его в endpoint человеческого решения.
Библиотечный вызов сам не создаёт манифест: получите `provider.identity()` и сохраните
digest модели и параметры вместе с результатом. CLI делает это автоматически.
Согласуйте дополнительные поля knowledge_status/knowledge_refs с бэкендером.

## Технические ограничения и источники

Контекст проверяется консервативно по UTF-8 объёму до отправки, диалог молча не обрезается.
Это может отклонить длинный вход, который токенизатор фактически вместил бы. Незавершённая
генерация — ошибка, не успех. В Ollama 0.32.14 обнаружена ошибка компиляции грамматики
с ограничениями длины в этой схеме: на проводе оставлены типы/поля/enum, а длины, число
результатов и смысловые ограничения строго проверяются после ответа в Python.

Адаптер сверён с официальными [Chat API](https://docs.ollama.com/api/chat) и
[Structured Outputs](https://docs.ollama.com/capabilities/structured-outputs).
JSON Schema проверяет форму, не гарантирует качество ML. Измеренные результаты запуска
и незакрытые зависимости фиксируются отдельно в `VALIDATION.md`.
