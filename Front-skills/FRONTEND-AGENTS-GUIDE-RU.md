# Команда frontend-агентов для Codex и Claude Code

Шесть специалистов и общий скилл **frontend-team**. Они используют уже собранные frontend-craft, frontend-qa, референсы Forte и нужные материалы ECC. Комплект расположен в этой папке; на рабочем столе доступен через ярлык `Frontend-Skills-Kit`.

## Как запустить

Открой нужный frontend-проект и начни новую сессию, чтобы приложение загрузило новые определения. Напиши:

**Codex**

> $frontend-team Сделай [экран/функцию] в этом проекте. Подключи нужных специалистов: дизайн, реализация и независимые проверки. Проверь адаптивность и основной сценарий в браузере, исправь найденные дефекты и покажи доказательства проверок.

**Claude Code**

> /frontend-team Сделай [экран/функцию] в этом проекте. Подключи нужных специалистов, проверь код, адаптивность и основной сценарий в браузере. Исправь найденные дефекты и покажи результат проверок.

**Только проверка существующего фронтенда**

> Используй frontend-team. Проведи ревью изменений и проверку интерфейса на маршрутах [маршруты]. Проверь код, дизайн, мобильную версию, формы и доступность. Файлы не меняй. Найденные ошибки опиши с воспроизведением и доказательствами; непроверенное отметь отдельно.

**Один специалист**

> Подключи frontend-code-reviewer и проверь текущий diff на реальные ошибки состояния, запросов и интеграции. Прочитай окружающий код и тесты. Ничего не меняй.

Имена агентов используются в обычном запросе на делегирование. `/frontend-team` — команда скилла в Claude; `/frontend-code-reviewer` не создаётся этой установкой как slash-команда.

## Кто за что отвечает

| Агент | Задача | Какие скиллы читает |
|---|---|---|
| `frontend-designer` | Композиция, типографика, токены, референсы, адаптивность и состояния; конкретный brief | frontend-craft |
| `frontend-builder` | Пишет интерфейс и нужные тесты, реализует поведение, исправляет подтверждённые дефекты | frontend-craft + frontend-qa |
| `frontend-code-reviewer` | Проверяет diff: состояние, async, формы, API, границы client/server, безопасность и регрессии | frontend-craft + frontend-qa + ecc-library |
| `frontend-browser-qa` | Открывает реальный UI, проходит сценарии, снимает и просматривает screenshots, проверяет размеры экрана | frontend-qa + frontend-craft |
| `frontend-a11y-reviewer` | Клавиатура, фокус, labels, семантика, ошибки формы, контраст, reduced motion | frontend-qa + ecc-library |
| `frontend-performance-reviewer` | Ищет измеримые проблемы загрузки и отзывчивости: bundle, сеть, render, layout, память | frontend-qa + ecc-library |

Главный агент управляет очередностью через [frontend-team](skills/frontend-team/SKILL.md). Все шесть специалистов постоянно запускать не нужно. Для небольшой правки достаточно прямой работы и короткой проверки. Для нового интерактивного экрана — brief → реализация → ревью кода → браузер; доступность и производительность подключаются по задаче.

## Как передаются знания и результаты

Каждая роль получает актуальные пути к своим `SKILL.md` и [общему протоколу](skills/frontend-team/references/agent-contract.md). В Claude также задан `skills` для предварительной загрузки нужных скиллов. Supporting files и картинки агент читает по необходимости: для дизайна выбирает 2–4 подходящих изображения, а не загружает все 63 в каждую задачу. ECC подключается через каталог, без активации всего runtime.

Общий скилл передаёт проект, цель, критерии готовности, файлы, текущий diff/снимок, URL, состояния и ограничения через [шаблон задачи](skills/frontend-team/assets/handoff-template.md). Агенту не требуется угадывать содержание другого чата. Это явная передача контекста, а не бесконечная память.

Приложение и тесты правит builder. Проверяющие возвращают замечания, затем builder исправляет их, и затронутые проверки повторяются. Браузером в один момент управляет один участник. После изменения кода старые screenshots и результаты помечаются устаревшими, если правка влияет на них.

Результат собирается по [шаблону отчёта](skills/frontend-team/assets/report-template.md): сделано, найденные дефекты, выполненные проверки, доказательства и ограничения. Нет браузера — визуальная проверка остаётся непроверенной. Нет измерений — нет выдуманного прироста скорости. Запрос «только ревью» не запускает автоматические исправления.

## Что установлено

- 6 определений Codex: `~/.codex/agents/frontend-*.toml`.
- 6 определений Claude Code: `~/.claude/agents/frontend-*.md`.
- Скилл frontend-team в `~/.agents/skills` и `~/.claude/skills`, вместе с прежними пятью скиллами.
- Определения подключены символьными ссылками к [Codex-адаптерам](agents/codex) и [Claude-адаптерам](agents/claude) этой папки.

Codex-файлы используют отдельные TOML-определения с name, description и developer_instructions. Claude-файлы используют Markdown, YAML frontmatter, `skills` и `model: inherit`. Оба варианта сгенерированы из одних [исходников ролей](agents/roles) и [общих правил](agents/common.md). Форматы сверены с официальными [Codex Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents) и [Claude Code Subagents](https://code.claude.com/docs/en/sub-agents), 30.10.2026.

Текущие модель, effort, конфигурация MCP и разрешения пользователя сохраняются. `~/.codex/config.toml` и настройки Claude установщик не меняет. У проверяющих Claude отключены Write/Edit/NotebookEdit и вложенное делегирование Agent. Это ограничение инструментов плюс инструкции, **не изолированная файловая песочница**: доступный shell/browser по-прежнему регулируется разрешениями родителя. В Codex запрет изменения исходников задан инструкциями роли.

Команда не устанавливает браузер, Playwright, Node или frontend-зависимости глобально. Она использует то, что есть в конкретной сессии и проекте. Новые named agents не запускаются в фоне сами по себе, hooks и расписания не создаются.

## Проверить или переустановить

Открой Terminal в папке комплекта. Для новых agent-helpers нужен Python 3.11+; внешние пакеты не требуются.

```sh
# Проверить совпадение адаптеров с исходниками
python3 scripts/render_agents.py

# Подключить все шесть скиллов и все шесть ролей к обоим инструментам
python3 scripts/manage_skills.py install --apply
python3 scripts/manage_agents.py install --apply

# Проверить подключения
python3 scripts/manage_skills.py status
python3 scripts/manage_agents.py status

# При необходимости подключить роли только к одному инструменту
python3 scripts/manage_agents.py install --target codex --apply
python3 scripts/manage_agents.py install --target claude --apply

# Проверки комплекта
python3 scripts/validate_kit.py
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
```

Без `--apply` установка/удаление только показывает план. Совпавшее имя чужого файла останавливает установку до создания ссылок; файл не перезаписывается. Повторная установка идемпотентна. Ошибка при создании ссылок откатывает уже созданные этим запуском ссылки.

Для изменения поведения редактируй [roles.json](agents/roles.json), [общие правила](agents/common.md) или конкретный файл в `agents/roles`, затем:

```sh
python3 scripts/render_agents.py --write
python3 scripts/validate_kit.py
```

Рендерер обновляет только подготовленные определения в комплекте. Изменения существующих скиллов читаются из их текущих файлов без переписывания всех ролей. Начни новую сессию после изменения конфигурации; автоматическое обновление ссылок уже открытым клиентом не проверено.

Перед перемещением папки выполни:

```sh
python3 scripts/manage_agents.py remove --apply
python3 scripts/manage_skills.py remove --apply
```

После перемещения/копирования на другой компьютер: `python3 scripts/render_agents.py --write`, затем обе команды `install --apply`. Рендерер обновит абсолютные пути. Удаление отсоединяет только ссылки этого комплекта, исходники и чужие агенты остаются. Ярлык на рабочем столе при перемещении тоже нужно обновить.

## Если роль не видна

1. Начни новую сессию в нужном проекте. В этой установке каталоги агентов создавались впервые; уже открытый Claude может не заметить новый каталог до перезапуска.
2. Выполни обе команды `status` и проверь, что ссылки ведут в существующую папку. Локальные настройки проекта или организации могут переопределять одноимённую роль.
3. Проверь поддержку custom agents установленной версией клиента. При отсутствии именованных ролей основной агент может передать сохранённые инструкции разрешённому обычному worker. Если делегирование недоступно, скилл выполнит этапы последовательно и прямо укажет, что независимого ревью не было.
4. Если скилл не обнаружен, передай агенту абсолютный путь к `skills/frontend-team/SKILL.md` в этой папке и попроси прочитать его. При отсутствии browser/MCP-инструментов сначала проверь окружение проекта; успешный build не заменяет браузер.
