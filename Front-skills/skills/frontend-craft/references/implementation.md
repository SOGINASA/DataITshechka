# От направления к рабочему интерфейсу

## Композиция по типу продукта

| Задача | Структурный приоритет | Типичная ошибка |
|---|---|---|
| Лендинг | Предметное обещание → доказательства/продукт → действие | Одинаковые карточки вместо убедительного содержания |
| Dashboard | Рабочая область → фильтры → данные/состояния → действия | Огромный hero и декоративные KPI без полезной задачи |
| Каталог | Поиск/категории → сравнимые товары → цена/действие | Разные размеры изображений и плавающие строки цен |
| Статья/портфолио | Типографика → последовательность → качественные медиа | Длинные строки и эффекты, мешающие чтению |
| Настройки/форма | Группы полей → понятная валидация → сохранение/отмена | Placeholder вместо label и потеря данных при ошибке |

## Токены

Извлекай существующие значения, затем добавляй недостающее. Минимально полезны `surface`, `surface-raised`, `text`, `text-muted`, `border`, `accent`, `on-accent`, `focus`, `success`, `warning`, `danger`; spacing и radius должны отражать роли. В проекте с другим именованием сохрани его.

Не делай новую дизайн-систему из одной кнопки. Для нового продукта зафиксируй небольшую шкалу, например 4/8/12/16/24/32/48/64, и осмысленные исключения. Сравни контраст в реальных состояниях, включая hover и disabled; muted не значит нечитаемый.

## Адаптивность

- У grid/flex детей проверяй `min-width: 0`; у колонок — `minmax(0, 1fr)`, если контент не должен растягивать сетку.
- Ограничь ширину основного контейнера, делай gutters адаптивными. Для больших таблиц допустим управляемый локальный scroll с понятным контекстом; вся страница не должна горизонтально уплывать.
- Мобильная композиция меняет приоритет, а не только уменьшает шрифт. Действие, фильтр и итог должны оставаться доступными.
- Сохраняй aspect-ratio изображений, резервируй место под async-контент. Sticky элементы не перекрывают фокус/поля и экранную клавиатуру.
- Проверь минимум один узкий и один широкий размер; для новой страницы обычно 390×844, 768×1024, 1440×900 плюс крайний размер, где ломается контент. Это тестовые точки, не обязательные CSS-breakpoints.

## Состояния и взаимодействие

Для каждого важного действия определи trigger → pending → success/error → следующий шаг. Для данных также empty, no-results, partial, permission, если они применимы. Не скрывай старые данные при небольшом обновлении без причины. Не дублируй отправку. После ошибки сохраняй введённые значения; после успешного изменения показывай реальное подтверждение.

Используй button для действия, link для перехода. Tabs, dialogs, comboboxes требуют полной клавиатурной модели; предпочитай подходящий существующий компонент. У dialog: имя, начальный фокус, удержание фокуса, закрытие и возврат фокуса. Не переноси незавершённый учебный пример как production-компонент.

## Детали, влияющие на качество

- Оптически выровняй иконки; сохраняй единый набор и толщину линий.
- Близкие вложенные скругления должны выглядеть концентрично; формула outer ≈ inner + padding помогает, но требует осмотра.
- Не меняй размеры кнопки при loading, hover или смене подписи.
- Указывай конкретные transition-properties. Небольшие переходы часто укладываются в 120–220 ms; важнее отзывчивость и смысл, чем точная цифра.
- Уважай reduced motion. Не прячь контент до JS/scroll-trigger без устойчивого fallback.
- Фото должно показывать продукт/контекст. Выбирай реальные доступные assets; генерируй только при наличии подходящего инструмента и задачи. Не рисуй сложную фотографию CSS-прямоугольниками.
- Текст и элементы управления остаются DOM/семантическими компонентами, даже если рядом есть AI-изображение.

## Работа с ECC

`frontend-design-direction` полезен для направления и доказательств; `make-interfaces-feel-better` — для доводки; `react-patterns` — для структуры; `react-performance` — после измерения проблемы; `motion-*` — если проект действительно использует соответствующий пакет. Общие рекомендации не требуют миграции стека, новой библиотеки, конкурентов или внешнего сервиса.

Отдельные замечания к исходным примерам перечислены в `ecc-library/references/compatibility.md` в этом комплекте. Если комплект недоступен, проверяй API по версии проекта и официальной документации.
