## Перенос в браузер

1. Сначала сохраняй действующий шрифт проекта. В новом продукте выбери роли, затем семейства. Не заставляй каждый dashboard использовать display-шрифт.
2. Для русскоязычного UI проверь «Ёжик съел щавель», длинное имя, дату, валюту, проценты и текст кнопки. Если нужен казахский — отдельно проверь Ә Ғ Қ Ң Ө Ұ Ү Һ І; наличие русской кириллицы не гарантирует эти глифы.
3. Убедись через браузер, что нужное семейство загрузилось, а не подменилось fallback. Используй только необходимые начертания, локальный WOFF2 при наличии, font-display и подходящий запасной стек.
4. Задавай масштаб по роли. Практичная отправная точка: body 16–18 px, UI 14–16 px, line-height текста 1.45–1.65. Это ориентиры, плотные интерфейсы могут требовать другого масштаба.
5. Заголовок должен выдерживать реальный текст: fluid size через clamp, ограниченная ширина, balance по ситуации. Не лечи overflow глобальным уменьшением всех шрифтов.
6. Для меняющихся чисел используй tabular-nums; для длинного URL — локальный overflow-wrap. Не разрывай обычные слова везде через word-break: break-all.
7. У длинного текста ограничь measure примерно 60–75 символами; на телефоне проверяй естественный поток, а не жёсткое число символов.
8. Не обрезай критический текст без способа прочитать его полностью. Не вставляй ручной `<br>` ради одного размера экрана, если он ломает остальные.

## Быстрый осмотр

- Заголовок замечается до описания, описание остаётся читаемым.
- Body не выглядит как рекламный слоган: обычное начертание, спокойный трекинг.
- Масштабирование до 200% не скрывает действия и сообщения.
- Длинная локализация не распирает навигацию и кнопки.
- Дизайн не зависит от трёх разных декоративных шрифтов.
