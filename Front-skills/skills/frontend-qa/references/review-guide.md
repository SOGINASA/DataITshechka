# Проверка визуального качества

## Порядок осмотра

1. **Задача:** понятно ли, для кого экран и какое действие главное? Рабочие данные/контролы находятся там, где их ожидают.
2. **Композиция:** иерархия, группировка, выравнивание, плотность. Нет случайных скачков отступов и бесконечных вложенных карточек.
3. **Типографика:** реальный шрифт, кириллица, числа, переносы, масштабирование. При уменьшении изображения главный смысл остаётся читаемым.
4. **Цвет:** контраст текста, контроля и фокуса; цвет дублируется текстом/формой для статусов. Проверить поддерживаемые темы отдельно.
5. **Поведение:** действия приводят к ожидаемому состоянию. Кнопки, ссылки, фильтры и формы не декоративные.
6. **Адаптивность:** узкий/средний/широкий экран, длинный контент, увеличенный текст. Нет перекрытия fixed/sticky элементами.
7. **Финиш:** изображения, иконки, мягкие границы, стабильные размеры, корректные hover/pressed/disabled/pending состояния.

## Доступность: конкретные проверки

- Обычный текст: контраст ≥4.5:1. Крупный текст: ≥3:1; крупный — от 18 pt (24 CSS px) либо 14 pt (~18.67 CSS px) при жирном начертании. Это пороги WCAG для текста, не универсальная оценка всей темы. [W3C Contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).
- В качестве удобного touch-ориентира используй 44×44 CSS px. WCAG 2.2 AA SC 2.5.8 задаёт 24×24 CSS px с исключениями по расстоянию, inline-ссылкам и др.; не выдавай 44 px за обязательный минимум этого критерия. [W3C Target Size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).
- Пройти Tab/Shift+Tab: порядок предсказуем, фокус видим, не скрыт sticky-элементами. Нативные buttons работают с Enter/Space; ссылки — как ссылки.
- У форм есть связанные labels, ошибки доступны через описание и семантику. Placeholder не заменяет подпись.
- Dialog имеет доступное имя, фокус внутри, Escape/закрытие и возврат на trigger. Проверить реальное поведение, не только ARIA-атрибуты.
- При reduced motion существенный контент не пропадает; обновления не требуют анимации, hover или цвета для понимания.
- Проверка axe не заменяет клавиатурную, визуальную и при необходимости screen-reader проверку. Не заявляй полное соответствие WCAG по одному чистому скану.

## Приоритет дефектов

**Блокирующий:** основное действие не работает, потеря данных, закрытый клавиатурный путь, критический контент недоступен.

**Существенный:** мобильный overflow, недоступные подписи/ошибки, нечитаемый текст, неверная обратная связь, заметное расхождение с brief.

**Доводка:** небольшая оптическая поправка, неровный ритм, неудачный перенос. Исправляй в рамках задачи, не превращай полировку в бесконечный редизайн.

## Доказательства

Для каждой проверки: маршрут + viewport + состояние + действие/команда + наблюдение + артефакт при наличии. Проверяй, что screenshot относится к актуальной версии. Если baseline отсутствует, честно зафиксируй это.

При исправлении сначала устраняй блокеры и структуру, затем типографику/ритм, затем детали. После правки достаточно повторить затронутые проверки, если не появилась новая причина расширить проверку.
